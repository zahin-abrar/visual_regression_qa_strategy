EXTERNAL TECHNICAL LEAD

https://github.com/actions/runner-images/issues/14484

This issue describes older Command-line Tools silently
creating Android API 37.0 AVDs with:

target=android-0

instead of:

target=android-37.0

An A/B reproduction found the same surfaceflinger
assertion and reported that Command-line Tools 22.0
corrected the AVD metadata and eliminated the crash.

Treat this as a strong hypothesis.
Our runner's actual CLI version and AVD target metadata
are still unknown.

TASK E — POST-BOOT EMULATOR STABILITY GATE

Current boot verification requires:
- adb state=device
- sys.boot_completed=1

Keep those requirements unchanged.

Add a separate bounded post-boot stabilization check
before APK installation.

Recommended observation period: approximately 45-60
seconds, with a small fixed polling interval.

Check:

1. Emulator process remains alive.

2. ADB remains authorized and responsive.

3. surfaceflinger is running.

4. system_server is running.

5. Both processes retain stable identities throughout
   the health observation window.

6. Android package manager answers a bounded, read-only
   query such as:
   adb shell cmd package list packages

7. No new matching fatal graphics crash is observed
   within the relevant observation window.

8. The known assertion and fatal-signal signatures are
   reported clearly if present.

Use process identities, timestamps and relevant logcat
evidence rather than an unconditional sleep.

Avoid clearing logcat or destroying useful evidence.

Handle:
- Temporary command failure
- Process disappearance
- Process restart
- ADB becoming offline/unauthorized
- Package manager timeout
- Emulator exiting
- Healthy device

A process that disappears or changes PID should not
be classified as stable merely because it reappears.

Bound every potentially hanging shell/ADB operation.
Do not allow the health gate to wait indefinitely.

Record concise diagnostics and a distinct failure
reason. Keep the gate reasonably fast for CI use.

Do not accept sys.boot_completed=1 alone as proof
that Android is healthy enough for screenshot testing.
