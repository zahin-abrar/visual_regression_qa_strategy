B. REQUIRED BEHAVIOR

For android_session():

1. If the test body fails:
   - Preserve the original exception object and traceback.
   - Attempt diagnostic collection.
   - Attempt app termination.
   - Attempt driver.quit().
   - Do not replace the original exception with secondary failures.
   - Make secondary failures visible using exception notes or an
     equally simple mechanism.

2. If the test body succeeds:
   - Attempt app termination and driver.quit().
   - Report cleanup failures rather than silently suppressing them.
   - If multiple cleanup operations fail, retain information about
     every failure.

3. Ensure driver.quit() is attempted even when termination fails.

4. Do not silently suppress errors that could cause false test passes.

5. Preserve current screenshot, comparison and artifact behavior.

For make_driver():

1. Inspect error handling after Appium session creation.
2. If app launch or scenario initialization fails:
   - Preserve the original launch exception and traceback.
   - Attempt termination and driver.quit() when a driver exists.
   - Report secondary cleanup failures without replacing the
     original launch failure.
3. Preserve behavior when WebDriver creation itself fails before
   a usable driver exists.

Use Python's existing exception facilities where practical.
Avoid additional dependencies or elaborate exception frameworks.
