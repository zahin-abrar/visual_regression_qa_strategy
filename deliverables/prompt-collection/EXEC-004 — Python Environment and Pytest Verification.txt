## Step 2 — Prepare an isolated Python environment

From PowerShell:

```powershell
cd D:\Projects\visual_regression_qa_strategy\qa_visual
```

If no usable local virtual environment exists:

```powershell
py -3.13 -m venv .venv
```

Use the virtual environment's Python executable directly:

```powershell
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip --version
```

If required packages are absent, install only dependencies declared by the existing runner:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Do not install packages globally, change system Python, or modify dependency pins.

If installation fails because of Python 3.13 compatibility or package-resolution issues, preserve the complete error and report the blocker. Do not independently switch Python versions or rewrite requirements.

## Step 3 — Verify dependency health

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pytest --version
```

Record actual outputs and exit codes.

## Step 4 — Verify pytest collection

```powershell
.\.venv\Scripts\python.exe -m pytest --collect-only -q
```

Record:

- Number and names of collected tests
- Import or collection errors, if any
- Command exit code

Successful collection does not count as successful test execution.

## Step 5 — Run existing unit tests

If the existing configuration defines the `unit` marker:

```powershell
.\.venv\Scripts\python.exe -m pytest -m unit -q
```

Record passed, failed, skipped, or deselected counts.

If no tests carry the `unit` marker, document that explicitly. Do not report zero collected tests as a passing unit-test suite.

Do not run the Appium integration test. Do not run an unfiltered pytest execution command that may create a device session.
