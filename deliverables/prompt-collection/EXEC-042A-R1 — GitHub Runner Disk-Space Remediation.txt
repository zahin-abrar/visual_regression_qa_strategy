OBJECTIVE

Remediate the disk-exhaustion failure observed in the
first GitHub Actions Android APK build.

Preserve the existing build architecture and add enough
diagnostics to establish whether cleanup is effective.

EVIDENCE

The first manually triggered workflow:
.github/workflows/android-build.yml

Result: FAILED after approximately 25m 27s.

Successful stages:
- Repository checkout
- Java 17 setup
- Node/pnpm setup
- pnpm install
- Expo Android prebuild

Failure stage:
- Gradle assembleDebug (x86_64)

Observed failures:
- java.io.IOException: No space left on device
  during Gradle/native compilation.
- System.IO.IOException: No space left on device
  while the GitHub Actions runner wrote its own
  _diag/Worker log.

The failure occurred during native Android compilation,
including CMake/Ninja tasks.

This is a confirmed disk-exhaustion event.
The precise disk consumers have not yet been measured.
