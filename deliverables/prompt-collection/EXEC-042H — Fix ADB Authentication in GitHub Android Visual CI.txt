
EXEC-042H — Fix ADB Authentication in GitHub Android Visual CI

PROJECT
D:\Projects\visual_regression_qa_strategy

Branch: main
Last reported commit: 8633843

PHASE
EXECUTION — Bounded CI infrastructure remediation

OBJECTIVE

Fix the ADB authentication failure preventing the
GitHub-hosted Android emulator from becoming accessible.

Initialize and verify a runner-local ADB authentication
key pair before starting the emulator.

Preserve the existing Android emulator configuration,
APK reuse, Appium setup and visual-testing behavior.

Do not rebuild the APK.

BACKGROUND

The latest GitHub Android visual workflow passed:

- Source build and artifact validation
- APK artifact download
- KVM functional verification
- Emulator dependency installation
- Android API 37 system image installation
- AVD creation
- AVD registration and discovery
- Emulator process startup

The AVD used:
- Pixel_10
- Android API 37
- x86_64
- 1080x2424
- 420 dpi
- 4096 MB RAM
- Headless cold boot
- SwiftShader graphics
- KVM acceleration

The emulator.log contained:

WARNING | Failed to open /home/runner/.android/adbkey
WARNING | adbkey generation failed
WARNING | No adb private key exists

The emulator also reported:

INFO | Boot completed in 118960 ms

However, ADB repeatedly reported:

adb: device unauthorized.

This adb server's $ADB_VENDOR_KEYS is not set.

Eventually, the workflow failed with:

sys.boot_completed not 1 within 420 s

IMPORTANT DISTINCTION

The emulator itself reported completing boot.

The workflow could not independently verify Android
boot completion because ADB never authorized the device.

The observed key-generation failure is established.

The exact reason automatic key generation failed is
NOT established.

Do not assume that setting ADB_VENDOR_KEYS alone will
resolve the problem.

TASK B — INITIALIZE HOST ADB AUTHENTICATION

Establish a usable ADB key pair before emulator launch.

1. Use the runner-local Android configuration directory
   expected by both ADB and the emulator.

2. Prefer the standard host key location:

   $HOME/.android/adbkey
   $HOME/.android/adbkey.pub

   unless existing configuration requires otherwise.

3. Create the parent directory if necessary.

4. Verify:
   - Directory existence
   - Directory ownership
   - Directory readability and writability
   - Current execution user
   - Effective HOME value

5. Apply suitable restrictive permissions.

6. If a valid key pair already exists, do not
   unnecessarily regenerate it.

7. If the key pair is missing, generate it using the
   supported Android platform-tools mechanism.

8. Verify the installed adb version and supported
   key-generation command before implementation.

9. Prefer adb keygen if supported by the installed
   version of platform-tools.

10. Ensure generation is bounded and exits nonzero
    when unsuccessful.

11. Verify both files exist and are nonempty.

12. Verify the private key can be read by the
    runner user.

13. Keep the private key restricted to that user.

14. Do not print the private key or public key contents.

15. Do not commit or upload generated ADB keys.

16. Fail with an actionable message if initialization
    cannot produce a usable key pair.
