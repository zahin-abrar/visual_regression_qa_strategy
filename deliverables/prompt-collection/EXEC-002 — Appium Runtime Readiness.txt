# EXEC-002 — Appium Runtime Readiness

**Project:** `D:\Projects\visual_regression_qa_strategy`  
**Phase:** EXECUTION  
**Previous task:** EXEC-001 — PASS

## Objective

Verify that the existing Appium 3.3.0 installation, UiAutomator2 7.1.2 driver, and Android emulator are ready for a native automation session.

Additionally, confirm that the emulator recognizes its updated 4 GB RAM configuration and that the existing Volksverpetzer application process remains alive.

**This task covers runtime readiness only. Do not initiate an Appium test session or modify the framework.**

## Instructions

1. Read `AGENTS.md` (if present) and `docs/AGENT_TASK_HISTORY.md`.
2. Run UiAutomator2's prerequisite doctor.
3. Verify that the existing `Pixel_10` Android emulator is online and fully booted.
4. Inspect the emulator's current memory configuration and application process using read-only ADB commands.
5. Check whether port 4723 already has a listening Appium server.
6. If no server is running, start Appium using `appium.cmd`, preferably in a separate terminal.
7. Query Appium's `/status` endpoint.
8. Record all verified results in `docs/AGENT_TASK_HISTORY.md` under EXEC-002.
9. Stop and return the evidence. Do not proceed to screenshot testing.

## PowerShell commands

### 1. Navigate to the project

```powershell
cd D:\Projects\visual_regression_qa_strategy
```

### 2. Check UiAutomator2 prerequisites

```powershell
appium.cmd driver doctor uiautomator2
```

Record any required dependency failures and optional warnings separately.

### 3. Verify emulator connectivity

```powershell
adb devices -l
adb shell getprop sys.boot_completed
```

Confirm that the expected `Pixel_10` emulator is online and that `sys.boot_completed` returns `1`.

### 4. Verify RAM and application process

```powershell
adb shell cat /proc/meminfo | Select-String 'MemTotal|MemAvailable'
adb shell pidof de.volksverpetzer.app
```

Record:

- `MemTotal` and `MemAvailable` values.
- Whether `MemTotal` is consistent with approximately 4 GB of emulator RAM.
- Whether `pidof` returns a process ID for `de.volksverpetzer.app`.
- Any command failures or unexpected results.

**Important:** A running process confirms that the application is currently alive. It does not independently prove long-term stability or that the correct QA fixture is displayed.

Do not terminate, relaunch, background, or interact with the application.

### 5. Inspect Appium server status

```powershell
Get-NetTCPConnection -LocalPort 4723 -State Listen `
    -ErrorAction SilentlyContinue
```

If an Appium server is already listening, inspect its status without starting a duplicate instance.

If no server is running, start Appium in a separate terminal:

```powershell
appium.cmd --address 127.0.0.1 --port 4723
```

Keep the server running if startup succeeds.

### 6. Query Appium readiness

From another terminal:

```powershell
Invoke-RestMethod `
    -Uri 'http://127.0.0.1:4723/status' `
    -TimeoutSec 10 |
    ConvertTo-Json -Depth 6
```

Record the response and any meaningful server startup messages.
